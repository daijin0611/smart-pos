# 门店关联关系重构 - 前端对接文档

> 变更日期：2026-04-01
>
> 本次重构将 **服务产品、服务项目、疗程券、优惠券、充值活动** 与门店的关系从 **一对一** 改为 **多对多**，通过通用关联表 `sys_org_relation` 管理。

---

## 变更概览

| 变更点 | 旧方案 | 新方案 |
|--------|--------|--------|
| 门店关联 | 实体自有 `orgId` 字段 | 通用关联表 `sys_org_relation` |
| 关联类型 | 一对一 | 多对多 |
| 查询参数 | 自动从登录信息取 orgId | 前端传 `orgId`（可选，不传查全部） |
| 新增/更新 | 单个 orgId | 前端传 `orgIds` 数组（`List<Long>`） |
| 响应字段 | `orgId: Long` | `orgIds: List<Long>` |

---

## 1. 服务项目 (ServerItem)

### 1.1 查询列表

```
GET /api/server/item/query-list
```

**请求参数（新增 `orgId`）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| keyWord | String | 否 | 关键字（名称/编码模糊搜索） |
| itemStatus | Integer | 否 | 状态（0 正常，1 停用，null 全部） |
| **orgId** | **Long** | **否** | **门店ID，不传则查全部门店的数据** |

**响应变更：** 每条记录的 `orgId: Long` → `orgIds: List<Long>`

```json
{
  "code": "200",
  "data": [
    {
      "id": 1,
      "itemName": "足疗按摩",
      "itemEncode": "SRV001",
      "serverTime": 60,
      "itemPrice": 100.00,
      "vipItemPrice": 80.00,
      "isDiscounts": 0,
      "commissionType": 1,
      "commissionValueRotation": 10.00,
      "commissionValueAppointment": 15.00,
      "commissionValueExtend": 12.00,
      "commissionBase": 0,
      "itemStatus": 0,
      "remark": "",
      "orgIds": [1, 2, 3]
    }
  ]
}
```

### 1.2 查询详情

```
GET /api/server/item/query-info?id={id}
```

**无变更**，响应中 `orgId` → `orgIds`（同上格式）。

### 1.3 新增服务项目

```
POST /api/server/item/add-item
```

**请求体变更（新增 `orgIds`）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| itemName | String | 是 | 服务项目名称 |
| itemEncode | String | 是 | 服务项目编码 |
| serverTime | Integer | 是 | 服务时长（分钟） |
| itemPrice | BigDecimal | 是 | 标准价 |
| vipItemPrice | BigDecimal | 是 | 会员价 |
| isDiscounts | Integer | 是 | 是否打折（0 允许，1 禁止） |
| commissionType | Integer | 是 | 提成类型（0 固定，1 比例） |
| commissionValueRotation | BigDecimal | 是 | 轮牌提成值 |
| commissionValueAppointment | BigDecimal | 是 | 点钟提成值 |
| commissionValueExtend | BigDecimal | 是 | 加钟提成值 |
| commissionBase | Integer | 是 | 提成基准（0 标准价，1 实收价） |
| itemStatus | Integer | 是 | 状态（0 启用，1 禁用） |
| remark | String | 否 | 备注 |
| **orgIds** | **List\<Long\>** | **否** | **关联门店ID列表** |

```json
{
  "itemName": "足疗按摩",
  "itemEncode": "SRV001",
  "serverTime": 60,
  "itemPrice": 100.00,
  "vipItemPrice": 80.00,
  "isDiscounts": 0,
  "commissionType": 1,
  "commissionValueRotation": 10.00,
  "commissionValueAppointment": 15.00,
  "commissionValueExtend": 12.00,
  "commissionBase": 0,
  "itemStatus": 0,
  "orgIds": [1, 2, 3]
}
```

### 1.4 更新服务项目

```
PUT /api/server/item/update-item
```

请求体与新增一致，额外包含 `id` 字段。`orgIds` 传 `null` 或不传表示不修改门店关联，传空数组 `[]` 表示清除所有关联。

### 1.5 修改状态

```
PUT /api/server/item/update-status?id={id}&status={status}
```

**无变更。**

## 统一变更规则

### 查询接口

- 所有列表查询新增可选参数 `orgId`（Long 类型）
- **不传 `orgId`**：返回全部数据（不限门店）
- **传入 `orgId`**：仅返回该门店关联的数据

### 新增 / 更新接口

- 所有新增和更新接口新增可选参数 `orgIds`（`List<Long>` 类型）
- `orgIds` 传具体的门店 ID 数组，建立多对多关联
- 更新时 `orgIds` 传 `null` 或不传：不修改门店关联
- 更新时 `orgIds` 传空数组 `[]`：清除所有门店关联

### 响应对象

- 所有 VO 响应中，原来的 `orgId: Long` 统一变更为 `orgIds: List<Long>`
- 详情接口响应同样包含 `orgIds` 字段

### 无变更的接口

以下接口不受本次重构影响：
- 所有 **状态修改** 接口（仅修改 status 字段）
- 优惠券统计接口 `GET /vip/ticket/count-ticket`
