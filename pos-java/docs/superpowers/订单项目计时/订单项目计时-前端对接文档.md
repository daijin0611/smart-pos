# 订单项目计时 - 前端对接文档

## 概述

订单服务项目计时功能，支持手动开始/暂停/恢复/停止，到期自动结束，到期前5分钟提醒。

计时数据挂载在订单明细（`orderDetails`）上，**无需新增查询接口**，通过现有的床位轮询接口即可获取计时状态。

---

## 数据模型

### OrderDetailVO 新增字段

订单明细对象新增以下 7 个字段，通过 `GET /order/query-by-bed-id/{bedId}` 返回：

| 字段 | 类型 | 说明 |
|---|---|---|
| `timerStatus` | Integer | 计时状态：0=未开始, 1=进行中, 2=已暂停, 3=已结束 |
| `timerStartTime` | String (datetime) | 计时开始时间，如 `"2026-04-09 19:24:37"` |
| `timerEndTime` | String (datetime) | 预计结束时间，如 `"2026-04-09 20:24:37"` |
| `timerPausedDuration` | Integer | 累计暂停总时长（秒），默认 0 |
| `timerLastPauseTime` | String (datetime) | 最近一次暂停开始时间，null 表示未暂停 |
| `actualDuration` | Integer | 实际服务时长（秒），仅 timerStatus=3 时有值 |
| `timerWarned` | Integer | 是否已触发到期前5分钟提醒：0=未提醒, 1=已提醒 |

### 响应示例

```json
{
  "code": 10000,
  "message": "操作成功",
  "data": {
    "id": 125,
    "orderCode": "ORD17757337927778640",
    "orderStatus": 1,
    "bedName": "T1",
    "orderDetails": [
      {
        "id": 266,
        "detailType": 1,
        "businessName": "足疗按摩",
        "serverType": 0,
        "timerStatus": 1,
        "timerStartTime": "2026-04-09 19:24:37",
        "timerEndTime": "2026-04-09 20:24:37",
        "timerPausedDuration": 0,
        "timerLastPauseTime": null,
        "actualDuration": null,
        "timerWarned": 0
      }
    ]
  }
}
```

> 只有 `detailType=1`（服务类型）的明细才有计时功能，产品（0）和疗程券（2）的 `timerStatus` 始终为 0。

## API 接口

### 基础路径

所有计时接口路径前缀：`/order/detail/timer`

### 1. 开始计时

**请求**

```
POST /order/detail/timer/start/{detailId}
```

| 参数 | 类型 | 位置 | 必填 | 说明 |
|---|---|---|---|---|
| detailId | Long | Path | 是 | 订单明细ID |

**响应**

```json
{ "code": 10000, "message": "操作成功", "data": "计时已开始" }
```

**前置条件**
- `timerStatus` 为 0（未开始）
- 订单状态为未结算（orderStatus=1）
- 明细类型为服务（detailType=1）
- 服务项目已配置服务时长（serverTime > 0）

**错误响应**

```json
{ "code": 9999, "message": "当前状态不允许开始计时", "data": null }
{ "code": 9999, "message": "服务项目未配置服务时长", "data": null }
{ "code": 9999, "message": "仅服务项目支持计时", "data": null }
```

---

### 2. 暂停计时

**请求**

```
POST /order/detail/timer/pause/{detailId}
```

**响应**

```json
{ "code": 10000, "message": "操作成功", "data": "计时已暂停" }
```

**前置条件**
- `timerStatus` 为 1（进行中）

**错误响应**

```json
{ "code": 9999, "message": "当前状态不允许暂停", "data": null }
```

---

### 3. 恢复计时

**请求**

```
POST /order/detail/timer/resume/{detailId}
```

**响应**

```json
{ "code": 10000, "message": "操作成功", "data": "计时已恢复" }
```

**前置条件**
- `timerStatus` 为 2（已暂停）

**说明**：恢复时后端会自动将暂停时长累加到 `timerPausedDuration`，并延长 `timerEndTime`。前端无需额外处理。

**错误响应**

```json
{ "code": 9999, "message": "当前状态不允许恢复", "data": null }
```

---

### 4. 手动停止计时

**请求**

```
POST /order/detail/timer/stop/{detailId}
```

**响应**

```json
{ "code": 10000, "message": "操作成功", "data": "计时已停止" }
```

**前置条件**
- `timerStatus` 为 1（进行中）或 2（已暂停）

**说明**：停止后 `timerStatus=3`，`actualDuration` 为实际服务时长（扣除暂停时间）。

**错误响应**

```json
{ "code": 9999, "message": "当前状态不允许停止", "data": null }
```

## 前端集成指南

### 1. 数据获取流程

无需新增请求，复用现有床位轮询：

```
前端轮询 GET /room/bed/query-all
  → 遍历床位，对 status=1（服务中）的床位
    → 请求 GET /order/query-by-bed-id/{bedId}
      → orderDetails 中已包含 timerStatus 等计时字段
```

### 2. 倒计时计算

前端根据返回字段本地计算倒计时展示，不需要频繁请求后端：

```javascript
/**
 * 计算倒计时（秒）
 * @param {Object} detail - OrderDetailVO 对象
 * @returns {number|null} 剩余秒数，null 表示无需倒计时
 */
function getCountdown(detail) {
  if (detail.timerStatus !== 1 || !detail.timerEndTime) {
    return null;
  }
  const end = new Date(detail.timerEndTime).getTime();
  const now = Date.now();
  return Math.max(0, Math.floor((end - now) / 1000));
}
```

### 3. 格式化倒计时

```javascript
function formatCountdown(seconds) {
  const h = Math.floor(seconds / 3600);
  const m = Math.floor((seconds % 3600) / 60);
  const s = seconds % 60;
  if (h > 0) {
    return `${h}:${String(m).padStart(2, '0')}:${String(s).padStart(2, '0')}`;
  }
  return `${m}:${String(s).padStart(2, '0')}`;
}
```

### 4. 状态展示逻辑

```javascript
function getTimerDisplay(detail) {
  switch (detail.timerStatus) {
    case 0:
      return { label: '未开始', type: 'default', countdown: null };

    case 1: {
      const seconds = getCountdown(detail);
      const isWarning = detail.timerWarned === 1;
      return {
        label: formatCountdown(seconds),
        type: isWarning ? 'warning' : 'primary',  // 到期前5分钟高亮
        countdown: seconds,
      };
    }

    case 2:
      return { label: '已暂停', type: 'info', countdown: null };

    case 3: {
      const duration = detail.actualDuration || 0;
      const minutes = Math.floor(duration / 60);
      const seconds = duration % 60;
      return {
        label: `已结束 ${minutes}分${seconds}秒`,
        type: 'success',
        countdown: null,
      };
    }

    default:
      return { label: '-', type: 'default', countdown: null };
  }
}
```

### 5. 操作按钮状态

```javascript
function getTimerActions(detail) {
  return {
    canStart:  detail.timerStatus === 0,       // 未开始 → 可开始
    canPause:  detail.timerStatus === 1,        // 进行中 → 可暂停
    canResume: detail.timerStatus === 2,        // 已暂停 → 可恢复
    canStop:   detail.timerStatus === 1         // 进行中 → 可停止
             || detail.timerStatus === 2,        // 已暂停 → 可停止
  };
}
```

### 6. 到期前5分钟提醒

```javascript
// 方式1：通过 timerWarned 字段判断（推荐）
// 后端自动标记 timerWarned=1，前端轮询时检查即可
if (detail.timerWarned === 1 && detail.timerStatus === 1) {
  // 显示到期提醒提示（如高亮、闪烁、提示音等）
  showWarningAlert(`${detail.businessName} 即将结束`);
}

// 方式2：前端本地计算（更实时）
const countdown = getCountdown(detail);
if (countdown !== null && countdown <= 300 && countdown > 0) {
  // 5分钟内到期，显示提醒
}
```

### 7. 状态流转图

```
timerStatus=0 (未开始)
    │
    │  POST /start/{detailId}
    ▼
timerStatus=1 (进行中) ◄──── POST /resume/{detailId}
    │         ▲                    ▲
    │         │                    │
    │    POST /pause/{detailId}    │
    │         │                    │
    ▼         └──── timerStatus=2 ─┘
    │               (已暂停)
    │
    │  POST /stop/{detailId}
    │  或 到期自动结束（后端定时任务）
    ▼
timerStatus=3 (已结束)
```

## 注意事项

1. **只有服务项目有计时**：`detailType=1` 的明细才需要展示计时功能，产品和疗程券忽略。
2. **到期自动结束**：后端每 30 秒扫描一次，到期后自动将 `timerStatus` 设为 3。前端轮询时会感知到状态变化。
3. **结算/取消联动**：订单结算或取消时，后端自动结束该订单下所有未结束的计时。
4. **加钟独立计时**：每个 OrderDetail 独立计时，加钟项目有自己的计时周期。
5. **暂停延长结束时间**：暂停后恢复，`timerEndTime` 会自动延长暂停的时长，前端无需额外计算。
6. **时间格式**：所有时间字段格式为 `"yyyy-MM-dd HH:mm:ss"`，前端解析时注意时区。
